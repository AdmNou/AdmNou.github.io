佚名 · AI 产品运营求职作品集

AI 产品运营要管的不是「一个确定的产品」，而是「一个输出不确定的模型」：定评测口径 → 建评测集 → 跑 badcase 归因 → 调 Prompt 与知识配置 → 把对话体验和成本质量一起压住。这个岗位的核心交付物是「一套别人能重跑的质量判断」，不是「我觉得挺好用」。
本作品集用两条真实主线证明这套动作我能独立跑完：①「选一本」AI 选本助手——定位、上线、24 条场景评测集设计、5 项 badcase 确认、当晚修复复测闭环；② 三平台门店 6 个月经营复盘——51 份官方后台导出、恒等式验口径、新老客分层与召回。

先说清 AI 产品运营和产品运营的关系，省得你觉得我是转行重开一局：不是「产品运营 + 一层 AI」，是同一副骨架、几个器官换了。产品运营那 9 项底座（用户研究 / 定位取舍 / 冷启动 / 数据口径 / 分层生命周期 / 内容活动 / 体验质量 / 跨团队推动 / 复盘迭代）我一项没少——其中 2 项换了载体（内容生产让给模型、质量判断从满意度问卷换成评测集）、1 项被显著加强（数据口径要加模型指标）、另加 3 项模型层能力（评测集设计 / Prompt 与知识配置 / 成本与质量权衡）。所以这一页先证明底座，再证明叠加层——两个岗位都能看。

作品一 · AI 产品落地：「选一本」智能笔记本电脑选购助手

面向大学新生与数码小白的「选购决策助手」。核心主张：把晦涩参数翻译成生活语言，一次给出【最优解 + 一个备选】；不接厂家 CPS、不做软文。时间线：2026.05 启动定位与调研，6 月曾计划寻找创业合伙人共同上线（未果），随后独立完成开发部署，并用 24 条场景的评测集完成首轮迭代。口径说明（主动声明）：本产品为演示版 MVP，暂无真实注册用户；页面中的数据均为本人 24 条场景评测集的自测结果，不是线上真实用户数据——真人试用是下一迭代项（实验设计见「推荐质量验证」页）。

主动交底一件事，省得你问到：当前版本的推荐主链路是本地加权规则引擎，不是大模型；「AI 会诊」是预留接口，接入模型后启用。为什么这么排：在接模型之前，先把评测集、评分口径、badcase 的记录方式建好——因为模型一接进来，你唯一能判断它好不好的东西就是这套集子。这也是我理解的 AI 产品运营的起手式：先有能力判断好坏，再谈调优；否则一接模型就只剩「感觉好像变聪明了」。

可读出的运营事实

  • 5 月是投产爆发期：曝光 5.6 万、订单 368 单、净额 5,780 元；但入店转化率被稀释到 5.5%（平月 6.5–7.6%）——买来的是泛流量，单靠活动不可持续。
  • 8 月是效率最高期：净额 6,650 元为全期峰值；同期三平台老客占比稳定在三成以上，复购是基本盘。
  • 4–5 月是从 0 起的爬坡期：首月 88 单 → 5 月 466 单，靠平台活动拉动，属冷启动阶段；增长和质量要分开看。
  • 美团靠曝光承接、京东淘宝靠老客召回：美团曝光量三平台最大（11.8 万）但新客占比高；京东/淘宝曝光小、老客占比稳定（32.3%/33.5%），适合召回。
  • 淘宝老客转化率碾压新客：老客下单转化 42.7% vs 新客 13.7%、老客进店转化 14.7% vs 新客 3.3%；但淘宝曝光 96.5% 给了新客——「曝光给新客、转化靠老客」的结构性错配，是私域与召回动作的直接依据。

作品三 · 可复用的运营方法论

① 数据复盘流程（这份看板就是这么出来的）
  • 先确认口径：区分「订单数」与「结算金额」；结算账单 ≠ 订单明细，不能用来数单量
  • 用恒等式验证字段含义，不靠猜（美团营业收入 = 优惠前总额 − 各项支出，154 天逐日误差 0）
  • 识别断档：区分「真实零单」与「未开店」，避免污染均值
  • 推算项单独标注，绝不与实测项混列；对不上的数字先查源，不许「两个都放着」
② 增长实验格式（假设 → 实验 → 数据 → 结论）
  • 每个运营动作先提假设，再用后台真数验证，证伪的照实写
  • 实例：平台活动能把曝光拉爆（5 月 +683%）但稀释入店转化——买来的是泛流量，单靠活动不可持续；三平台私域群合计 100+ 人（淘宝 80+/美团 25/京东若干），验证后把触达重心收回平台内工具
③ 用户分层与复购打法
  • 后台无客户级明细，所以用平台官方的新老客分层做打法设计，不硬造 RFM 分数——口径诚实优先于框架好看
  • 数据依据：老客占比 京东 32.3% / 淘宝 33.5% / 美团 39.6%；淘宝老客下单转化 42.7% vs 新客 13.7%；打法：京东/淘宝做老客召回，美团做曝光承接
  • 召回与锁客（2026.04–09 运营期内真实做过）：① 对当日下单用户逐单电话回访——问口味分量、收集改进建议、预告「下次送点小菜」，收到过顾客主动好评；② 借平台连续下单返券活动串复购（满 N 单送券）；③ 引导顾客充值京东外卖饭卡（储值仅限本店消费、有顾客实际充值、后台可查），用预付款锁定后续消费
④ 语境迁移地图（外卖店 ↔ 互联网产品运营）
  • 同一套动作，换一个载体：家庭外卖店是「产品」，三平台后台就是「产品后台」，顾客就是「用户」
  • 买量活动 → 渠道投放与 A/B 测试：曝光拉爆但转化被稀释，等价于投放 ROI 与着陆页转化问题
  • 新老客分层 → 用户分层精细化运营：按平台官方分层口径设计召回策略，不硬造模型分
  • 连续下单返券 + 饭卡储值 → 促活与权益玩法：平台券是活动位，饭卡是预付款锁客（储值仅限本店消费）
  • 逐单电话回访 → 用户调研与关系运营：问口味分量、收集改进建议、预告下次赠菜，把口碑做在差评发生之前
  • 24 条场景评测集 → 模型产品的质量回归：7 类用户场景 × 完整问诊流程，同一套集子可在任意版本重跑做前后对照，5 项 badcase 当晚修复复测
  • Prompt 约束设计 → AI 产品运营的红线管理：反幻觉（不许编造参数 / 价格 / 承诺）、结构化输出、不确定就说不确定——这是 AI 产品区别于普通产品的核心运营动作
  • 竞品调研 → 竞品与行业监控：拆解京东AI购的留存 / 促活 / 裂变设计，产出带验证指标的建议
  • 我缺的是 APP 语境的工时，不缺的是同一套动作在另一个载体上的执行
⑥ AI 产品评测方法论（AI 产品运营与普通产品运营最不一样的地方）
  • 普通产品的体验好坏靠 A/B 和留存说话；模型产品的输出是不确定的，同一个提问跑两次可能不同——所以必须先把「什么叫好」写成可打分的口径，否则质量只能靠感觉
  • 四步闭环：定目标（这次评测要回答什么问题）→ 建集子（覆盖真实用户分布 + 边缘 + 对抗）→ 定指标（硬门槛 + 质量维度双层评分卡）→ 跑与对照（同一套集子跨版本重跑）
  • 三种评审方式的分工：可自动化的客观指标先跑（预算内率 / 序列一致性 / 入口可用性）；主观维度留人工复核；AI 辅助初评只做初筛，结论必须由人确认
  • 反模式（我踩过并改掉的）：① 指标太泛（「回答质量好」这种没法打分）② 只跑一遍不看对照（不知道是改好了还是改坏了）③ 把测试假象当结论（剪贴板污染那次，用对照实验排除后才写进报告）
  • 落地到本案：24 条场景 / 7 类用户 / 双层评分卡 → 首卡预算内率 2/24 → 修复后抽查 4/4，完整过程见质量评测页
⑤ 推广打法对标（我的动作 ↔ 平台官方工具 / 行业通行打法）
  • 不是随手做的，每一项都能对标到官方文档或行业验证过的打法：
  • 满减 / 折扣活动配置 ↔ 美团官方《新商家服务手册》三大自营销工具：减配送费（1–3 元提升入店量）、满减三档设计（引流档提高进店转化 / 凑单档提客单价 / 防拆单档）、折扣商品选热销品阶梯展示A 美团官方
  • 连续下单返券 ↔ 平台集点返券类频次激励工具——美团新商家 11 项新手任务中即含「设置集点返券」A 美团官方
  • 京东饭卡储值 ↔ 行业通行储值锁客：充值赠金、资金沉淀、限定本店消费（具名案例：熊大爷现包饺子会员储值累计破亿）C 具名案例
  • 新老客分层打法 ↔ 用户分层精细化运营；后台无客户级明细，故用平台官方分层口径、不硬造模型分B/C 行业通行
  • 电话回访 + 预告赠菜 ↔ 关系运营与情感连接，私域打法的一环C 行业通行
  • 评价运营四模块 ↔ 美团新商家任务明列「维护用户评价」，评分是平台流量分配的输入A 美团官方
  • 平台活动 + 小额充值投放（本人动作：参加平台官方活动拉曝光，美团曝光 7,139 → 55,951；充值投放每次 50 元、频次不高、美团为主京东淘宝很少，充值记录后台可查）↔ 官方建议姿势：美团培训《点金推广入门技巧》明言「经常建议新商家先用 50 元预算进行试投」；出价参考系统建议价、小幅慢调A 美团官方培训
  • 投放决策（充完看曝光 / 进店数据决定加不加，数据不支撑不加）↔ 行业通行：新店以测试为主、不盲目放大，成熟期店铺投放约占营业额 8–10%；预算集中曝光主战场（美团曝光三平台最大 11.8 万，京东淘宝曝光小、走老客复购）B/C 行业通行
  • 多平台推广工具认知（美团点金推广与京东「京准通门店推广」均为充值制投放工具）↔ 行业通行：按平台特性分配预算、不均匀撒布B/C 行业通行
  • 私域粉丝群 ↔ 行业重点私域社群玩法C 行业通行——三平台建群合计 100+ 人（淘宝 80+/美团 25/京东若干），验证后把触达重心收回平台内工具
